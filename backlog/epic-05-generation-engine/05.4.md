### 05.4 — `migrate` + `check` modes

**What & why.** `migrate` is what actually delivers the ADR-059 shape into a project that already
exists in the old flat layout — sync alone can't, because the shape change touches project-owned
files sync deliberately never writes. `check` is the standing readiness signal for both new and
migrated projects.

**This increment.**
- **`migrate`** — built on T9's discipline from Mompa's own ten single-use migration scripts:
  split flat epic files into per-story files, generate index rows from structure (never invent
  one), evict done rows to `CLOSED.md`, rewrite every affected link, verify every relocation
  byte-identical by script (`cmp`, not by eye), then run `board:check` as the acceptance test.
  Dry-run by default.
- **`check`** — reports structural validity (do the files exist, do they parse, does
  `board:check` pass) *and* completeness (how many `(to define)` gaps remain open) as two
  distinct signals — an incomplete-but-valid project is not the same as a broken one.
- `MANAGED` (the sync/renderer's framework-owned file list) grows from 8 to roughly 15 entries to
  cover `product-check`, `status-guard.sh`, `board-check.mjs` + its test, `check-links.mjs`,
  `index-backlog.mjs`, and the CI workflow template.
- **QCode-Method migrates itself first.** This repo's own board — deliberately left in the v1
  shape by 01.1 — is `migrate`'s first real run: a rehearsal on a repo fully controlled by the
  person building the tool, before it's ever pointed at Finosonido.

**Acceptance criteria.**
- Running `migrate --dry-run` against QCode-Method's own v1-shaped board reports every file it
  would split/move, with zero deletions in the additive passes (`git diff --numstat` proof).
- Running it for real converts this repo's own backlog to the ADR-059 shape, and
  `npm run board:check` (or the zero-dependency equivalent) exits 0 immediately after.
- `qcode check .` against the migrated result reports "structurally valid."

**`lib/qcode-migrate.mjs`** is the new parsing/transform engine — pure functions only, unit-tested
against synthetic fixtures built from this repo's own real, structurally awkward content, not
idealized ones. Two edge cases in particular exist because this repo's real epic files have them:
epic-02's four closures appear in the order 02.1/02.3/02.4/02.2 (close-order, not story order), and
epic-03's own `#### Closed: 03.2` block sits textually *before* its own `### 03.2` story heading
(both were closed in one pass; 03.2's spec section was filled in further down afterward). A parser
assuming "the closure between story N and N+1 belongs to story N" gets both silently wrong; the
actual parser matches blocks purely by id, wherever they sit. 29 tests total in this file.

**Verified against the real, live repo — not a synthetic fixture — at every stage**, using a
technique worth naming: since the real migration was uncommitted, `git archive HEAD -- backlog
PROJECT-STATUS.md ...` reliably reconstructed the true pre-migration v1 tree into a disposable
scratch copy for repeated full rehearsals (`--write`, then real `board-check.mjs`/`cockpit`
self-tests, copied in from the templates), without ever risking the real repo mid-iteration. Only
once a rehearsal came back fully clean was the same command run for real, in place, on this repo.

**Real bugs found and fixed, roughly in the order they surfaced — this was the highest bug count of
any story this build, proportional to being the first one to move real, irregular, already-written
prose rather than rendering fresh template content:**

1. **The "not yet filled in" placeholder heading (`#### Closed: 05.1–05.4`) has no ` — DATE` suffix
   at all** — unlike a real closure, so the original regex (`/^#### Closed: (\S+) — (.+)$/`) simply
   didn't match it, and the line fell through as plain content onto whatever block was still open,
   corrupting story 05.4's own body with the placeholder's text. Found by the unit suite, not
   inspection. Fixed with a two-step match: any `#### Closed: ...` heading is recognized first, then
   its content is tested against the real `ID — DATE` shape; a non-match becomes a reported, dropped
   stub instead of silently-swallowed content.
2. **A leading blank line right after every heading doubled up** once `renderStoryFile` added its
   own separator on top of one already captured in the body. Fixed by trimming leading (not just
   trailing) blank lines when a block is extracted; locked in with a test asserting no run of two
   blank lines survives a real heading+body+closure render.
3. **`CLOSED.md` rows nested one markdown link inside another.** `parseRecentlyDone` captured a
   Detail cell's whole raw text — link syntax and all — as `detailText`, and `renderClosedRow` then
   wrapped that in a *second*, new link. Found by reading the actual rendered rows, not assumed
   correct because the row count was right. Fixed by parsing the cell into its label + trailing
   prose, discarding only the old link wrapper.
4. **The "Last shipped" narrative bullet's href never got fixed** — the first pass only rewrote
   hrefs inside specific table cells, but that bullet reuses the exact same href string as its
   Recently-done row outside any table. Fixed by collecting every old→new href mapping into one map
   from every table the code already parses, then applying it as one global replace across the whole
   file — which incidentally made the fix simpler, not just more correct.
5. **Section insert/remove left inconsistent blank-line counts** (a 3-blank-line run in one spot, a
   missing blank line before a heading in another) — non-greedy regex lookahead for "up to the next
   heading" doesn't reliably leave exactly one blank line on both sides once something is spliced in
   or cut out. Rewritten as three small, explicit index-splicing helpers
   (`removeSection`/`insertSectionAfter`/`insertAfterHeading`) that trim each side's whitespace down
   to zero and rejoin with an explicit, known separator — verified with an `awk` pass over the real
   output asserting zero multi-blank-line runs and zero headings missing their leading blank line.
6. **"How status works"'s own last bullet said a story "moves to Recently done"** — true of the v1
   shape, false the instant that section is gone. Not new content: a direct, unavoidable consequence
   of the shape change, the same category as the href fixes, not a place to be conservative about
   "just relocate what's there." Replaced with the template's own correct wording (comes off the
   board, appends to `CLOSED.md`).
7. **The worst one: the "Where the detail lives" bullets silently never got inserted on this repo's
   own real first run**, even though every rehearsal against synthetic/partial fixtures had looked
   clean. Root cause: the guard `!newStatus.includes('backlog/CLOSED.md')` false-positived, because
   fix #6's own replacement text *also* contains the literal string `backlog/CLOSED.md` and runs
   first — by the time the guard checked, its trigger string was already present for an unrelated
   reason. Only caught by reading the actual migrated `PROJECT-STATUS.md` end to end after the real
   run, not by trusting the dry-run summary or the file-count. Fixed by guarding on the bullets' own
   unique label instead of a generic substring; the real repo's file was hand-patched to match once
   the fix landed (re-running `migrate` wasn't an option — it now correctly reports "already
   migrated").
8. **`check` mode's hard requirement for `.qcode/config.json` would have failed against this exact
   repo** — QCode-Method's own repo was hand-bootstrapped by 01.1, before `.qcode/config.json` was
   ever introduced, so it has none. But `check`'s only two jobs (self-test, gap-count) are both
   plain filesystem operations that never touch config. Relaxed the gate to `PROJECT-STATUS.md`'s
   presence (matching `migrate`'s own gate) instead; config is now read for informational display
   only.
9. **The backlog shape alone doesn't make `board:check` runnable at all** — a genuinely v1 project
   predates `scripts/board-check.mjs` by definition (this repo never had a copy of its own until
   this story). Without installing it, this story's own acceptance criterion ("`board:check` exits 0
   immediately after migrate") would be untestable, not just unmet. Added a tooling-install step to
   `migrate` using the same `renderProject` mechanism `sync` uses.
10. **That install step was first written too broadly** (`filterOwner: 'framework'`, matching
    `sync`'s own full scope) and installed `.claude/skills/*` too — which introduced 30 *new*, real
    dead links (`architecture/`, `product/`, `CLAUDE.md`, `handoffs/README.md` — files a real
    scaffolded consumer project has and this framework repo doesn't, since it's the framework, not a
    project built on it). Narrowed to just `scripts/`+`cockpit/`+`githooks/`+`ci/` — what
    `board:check`/`check:links`/the cockpit actually need; installing the lifecycle-gate skills into
    an existing project is a separate, bigger decision `sync` remains the right place for, not
    something `migrate` should do silently as a side effect.
11. **The tooling-install step was gated behind "already migrated," so it silently never ran** the
    second time — a real control-flow gap: refreshing the operational tooling is independently useful
    (and idempotent) whether or not the backlog was already reshaped. Restructured so
    `installOperationalTooling` runs unconditionally on every `--write` call, moved to a shared
    function both branches call.
12. **The first real, unfiltered `board:check` run against this repo's own root** (the very first
    time ever — this repo never had a working copy of the checker before this story) failed rule 5:
    `check-links.mjs`, now genuinely walking the whole tracked tree, found the embedded
    `qcode-project-scaffolder/assets/templates/` source and correctly reported its relative links as
    dead (they're calibrated for a file's *rendered* position, not its template-source position) —
    the same known class of artifact 02.3's closure already documented, just never actually
    encountered end-to-end because no repo had run the real checker unfiltered before. Since Mompa's
    own `check-links.mjs` already excludes its embedded scaffolder templates for the exact same
    reason (per 02.3's own note), ported that exclusion for real rather than re-deferring it a third
    time: any path under `assets/templates/` is now dropped from both the git-tracked and walk-
    fallback file lists — a no-op for every project that doesn't embed a scaffolder this way, which
    is every project except this one. Two new tests lock it in (excludes the embedded path, leaves an
    unaffected project's file list untouched); the real repo's installed copy was refreshed via
    `migrate` again once the template fix landed. 42 tests now in `lib/qcode-core.test.mjs`.
